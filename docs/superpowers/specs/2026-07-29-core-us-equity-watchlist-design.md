# 核心美股逐日固定展示设计

日期：2026-07-29

## 目标与成功标准

晨报新增独立的“核心股票表现”结构化区块。每个 A 股交易日生成的报告都必须逐只展示批准的固定股票；任何单只股票取数失败时保留该行并显示核验状态，不得静默省略、使用新闻数字补值或由模型推测。

每行固定字段为：分类、公司、代码、上市市场、收盘价、绝对变化、涨跌幅、行情日期、核验状态和来源。行情必须锁定到对应市场在中国早晨采集时已经完成的最近交易日。

## 方案选择

采用“配置化固定篮子 + 结构化行情采集 + 确定性报告渲染”。不采用模板硬编码，因为会让抓取、证据和展示名单漂移；不采用新闻文本提取作为必显机制，因为新闻覆盖不稳定且无法可靠证明行情日期。

扩展关注股票每日同样采集和展示。已核验新闻提到固定篮子之外的股票时，新闻仍可正常发布，但本阶段不从自由文本自动创造代码或行情；只有加入配置、明确交易所代码并通过结构化行情验证后，才升级为每日固定股票。这一边界防止同名公司、代码变更或新闻幻觉污染数值区块。

## 数据流与来源规则

1. `config/instruments.json` 新增 `us_core_stocks` 配置数组；每项包含分类、中文名称、代码、市场、单位、会话规则和至少一个结构化来源。
2. 美国上市股票优先复用腾讯明确日期快照和东方财富历史日线作为两个独立来源。来源值、前收盘、绝对变化和涨跌幅必须同日期、同上市代码且在既有容差内，才能标记双源核验。
3. SK 海力士使用韩国主上市代码。若可用免费来源不能同时证明同一交易日，则保留单源原值或显示不可用，不使用美国场外报价替代主上市行情。
4. `MarketCollector` 将普通宏观品种、行业 ETF 和核心股票分别收集，核心股票结果写入 `market.core_stocks`，但每只股票继续复用统一 `Observation`、`VerificationResult`、日期锁和数值容差。
5. TradingView 等无法独立证明行情日期的响应只能作为补充证据，不能单独把股票升级为“已双源核验”。新闻不能承担行情数值来源角色。
6. Markdown、HTML 和 `evidence.json` 同时保存完整核心股票结果。必显股票即便 `unavailable` 也必须生成一行。

## 日期与异常处理

- 美国股票使用上一完整 NYSE/Nasdaq 会话；美股尚未收盘时不得展示当日盘中值。
- 韩国股票使用中国采集时点之前已经完成的韩国主板交易日。若免费日历无法证明节假日，双源日期一致但目标会话不能严格证明时只标单源/待核验，不冒充严格双源通过。
- 来源日期不一致、代码不匹配、前值缺失、非有限数、涨跌幅无法由现值和前值复算、差异超容差时均降级为冲突。
- 单一来源失败不影响整份晨报生成；错误只记录来源类型，不在报告或日志泄漏响应正文、凭证或本机隐私路径。

## 报告布局

“核心股票表现”位于“美股三大指数”之后、“美股行业表现”之前，按四个分类分组。表格列为：公司（代码／市场）、核验状态、收盘价、绝对变化、涨跌幅、数据日期、来源。

报告告警新增固定篮子完整性检查：若任何批准的必显行缺失，报告生成视为结构错误；若行存在但行情不可用，则允许生成并在告警中列出不可用数量和股票代码。

## 测试与验收

- 配置测试：固定名单、分类、顺序、代码唯一性和来源字段有效。
- 单元测试：核心股票采集复用正确会话日期；双源一致、单源、冲突、错误日期和不可用分支。
- 报告测试：Markdown/HTML 每只固定股票均出现，并包含值、变化、日期、状态和来源；不可用股票仍保留行。
- 集成测试：流水线模型和 `evidence.json` 保留 `market.core_stocks`，不影响指数、板块、商品、宽度及新闻。
- 现场预览：以明确上海时间运行隔离报告，核对美股未开盘时只使用上一完整收盘，正式 `reports/latest` 在验收完成前不覆盖。
- 最终门禁：全量 unittest、Python 编译、JSON、shell/plist、HTML 静态结构、完整补丁与隐私范围检查；本目录不是 Git 仓库，因此提交和推送不适用，也不擅自初始化 Git。
